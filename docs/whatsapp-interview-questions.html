Spring Boot & microservices

What is the primary goal of the Spring Boot framework?
Spring Boot
Answer: Simplify configuring and deploying Spring applications (auto-configuration, starters, embedded servers — not a replacement language, and not “replace Spring entirely”).

Relational DB on EC2 needs a single EBS volume supporting up to 16,000 IOPS. Which volume type?
AWSEBS

Kubernetes

In Kubernetes, which API object is used to manage rolling updates for deployments?
Kubernetes
Answer: Deployment (strategy type RollingUpdate). ReplicaSet maintains replicas; StatefulSet/DaemonSet are other workload controllers. “RollingUpdate” alone is a strategy, not the primary API object — if options list Deployment-related choices, pick Deployment; if the listed options were ReplicaSet / RollingUpdate / StatefulSet / DaemonSet, the intended exam pick is often the Deployment’s rolling-update mechanism (commonly mis-optioned as “RollingUpdate”). Prefer: Deployment with RollingUpdate strategy.
If the MCQ options literally were ReplicaSet, RollingUpdate, StatefulSet, DaemonSet (no Deployment), the closest intended choice is usually RollingUpdate as the update strategy name — but in real K8s, you configure that on a Deployment.

Coding challenge

Java API Fetch and Count — GET https://coderbyte.com/api/challenges/json/all-posts, return/print the number of posts.
JavaHTTPJSON
Approach: HTTP GET the URL, parse JSON array, return array.length, print Number of posts: X. Use HttpClient (Java 11+) or HttpURLConnection + Gson/Jackson. 
public static int fetchAndCountPosts() throws Exception {
    HttpClient client = HttpClient.newHttpClient();
    HttpRequest req = HttpRequest.newBuilder(
            URI.create("https://coderbyte.com/api/challenges/json/all-posts"))
            .GET().build();
    String body = client.send(req, HttpResponse.BodyHandlers.ofString()).body();
    JsonArray posts = JsonParser.parseString(body).getAsJsonArray(); // Gson
    int count = posts.size();
    System.out.println("Number of posts: " + count);
    return count;
}

Java & concurrency

Minimum Cost Path — implement minpath(List<List<Integer>> a) from top-left to bottom-right minimizing sum of cell costs. N,M ≤ 50.
DPJava
Answer approach: Classic DP grid path (right/down only, unless stated otherwise). Let dp[i][j] = a[i][j] + min(dp[i-1][j], dp[i][j-1]) with careful first row/column fills. Examples cited: 5×5 → 327; 2×2 → 63. 
public static int minpath(List<List<Integer>> a) {
    int n = a.size(), m = a.get(0).size();
    int[][] dp = new int[n][m];
    dp[0][0] = a.get(0).get(0);
    for (int j = 1; j < m; j++) dp[0][j] = dp[0][j-1] + a.get(0).get(j);
    for (int i = 1; i < n; i++) dp[i][0] = dp[i-1][0] + a.get(i).get(0);
    for (int i = 1; i < n; i++)
        for (int j = 1; j < m; j++)
            dp[i][j] = a.get(i).get(j) + Math.min(dp[i-1][j], dp[i][j-1]);
    return dp[n-1][m-1];
}

SQL & performance

From table olympic, list each country’s athlete count; only countries with more than five athletes. Columns: country | athlete count.
SQL
Answer: 
SELECT country, COUNT(*) AS "athlete count"
FROM olympic
GROUP BY country
HAVING COUNT(*) > 5;

Query causes high disk I/O from excessive sorting. What optimization reduces sorting overhead?
SQL tuning
Answer: Create an index on the sorting columns (ORDER BY / GROUP BY keys) so the engine can avoid or reduce filesorts. Parallelism/MAXDOP/NOLOCK are not the primary fix for sort I/O.

Optimize: SELECT * FROM orders WHERE status = 'pending' AND total_amount > 100; (select all that apply)
SQL tuning
Good techniques:
  • Index on status (and/or composite with total_amount)
  • Index on total_amount if selective
  • Covering index including selected columns
  • Replace SELECT * with needed columns
Partitioning by status can help very large tables but is heavier than indexing.
