The problem

Given an array of numbers, return a new array where each slot holds the factorial of the matching input number.

A factorial means “multiply every whole number from 1 up to n.” So 3! = 3 × 2 × 1 = 6 and 5! = 5 × 4 × 3 × 2 × 1 = 120. By definition, 0! = 1.

InputOutput
{3, 5}[6, 120]
{5, 3, 5, 0, 4}[120, 6, 120, 1, 24]

The big idea: build a lookup table once

Factorials build on each other. Once you know 4! = 24, getting 5! is a single multiplication: 24 × 5 = 120. You never need to start again from 1.

So instead of computing each answer separately, the class:

  1. Looks for the biggest number in the input.
  2. Fills a table of factorials from 0! up to that biggest number, each one computed from the one before it.
  3. Answers every input by simply reading its slot in the table.
Analogy: instead of walking to the shop separately for every item on your list, you walk once to the farthest aisle you need, filling your basket along the way, and then hand out items from the basket.

Step-by-step walkthrough

Using the input {5, 3, 5, 0, 4}:

Step 1 — Find the biggest number

Scan the array once. The largest value is 5, so the table only needs to go up to 5!. While scanning, any negative number stops the method with an error, since negative factorials are not defined.

Step 2 — Build the table fact[0..5]

Start with fact[0] = 1. Each next slot is the previous slot times its index.

What each method does

MethodPlain-English role
factorial(int[] nums) The fast version. Finds the max, builds the table once, then fills the result by lookup. Returns an empty array for null or empty input.
factorialNaive(int[] nums) The slow comparison version. Computes every factorial from scratch, one input at a time.
factorialOne(int n) Helper for the naive version: multiplies 2 × 3 × … × n. Starts at 2 because multiplying by 1 changes nothing.
main Runs both versions on sample inputs and prints the results so you can see they agree.
Private constructor Prevents anyone from creating a FactorialArray object. Every method is static, so the class is just a toolbox.

The core of the fast method

// Build the table once
long[] fact = new long[max + 1];
fact[0] = 1L;
for (int k = 1; k <= max; k++) {
    fact[k] = fact[k - 1] * k;   // reuse the previous factorial
}

// Answer every input by lookup
for (int i = 0; i < nums.length; i++) {
    result[i] = fact[nums[i]];
}

Why it is faster than the original sketch

The original idea recomputed each factorial from 1 every time. For the input {5, 3, 5, 0, 4} that repeats a lot of the same multiplications:

ApproachWork doneBig-O
Naive (recompute each) 5! from scratch, 3! from scratch, 5! from scratch again, … About the sum of all input values
Lookup table (this class) Build up to 5! once, then one read per input O(n + max) time, O(max) extra space
The gain is biggest when the array is long, values repeat, or values cluster in a small range. For a tiny array like {3, 5} both versions are instant; the difference matters at scale.

Bugs in the original sketch

  • nums.lenth should be nums.length.
  • The inner loop incremented i++ instead of j++, so it never advances correctly.
  • Starting the multiplication at j = 0 multiplies the result by zero and wipes it out. Start at 1 or 2.
  • factorialInput was declared twice.
  • Missing semicolons, and an unused calculatedList array.
  • Using int for results overflows from 13! onward; the class uses long instead.

Limits: overflow and negatives

Overflow: a long holds factorials correctly only up to 20!. From 21! onward the value silently wraps around to a wrong (even negative) number. The class does not check for this. If inputs can exceed 20, either reject them up front or switch the table to BigInteger.
  • Negatives: any negative input throws IllegalArgumentException.
  • Very large max: the table size equals the biggest input, so a single huge value makes a big table even if every other input is small.

Interview summary

One-liner: find the largest input, build a factorial table once by multiplying each entry by its index, then answer every input with an O(1) lookup — O(n + max) overall instead of recomputing each factorial from scratch. Mention the long overflow limit at 20! and BigInteger for anything larger.
