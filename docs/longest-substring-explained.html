Problem

Given a string s, find the length of the longest substring without duplicate characters.
InputOutputExample substring
"abcabcbb"3"abc" (also "bca", "cab")
"bbbbb"1"b"
"pwwkew"3"wke" — not "pwke" (that is a subsequence, not a substring)
Substring vs subsequence: a substring is contiguous. "pwke" skips characters, so it does not count.

Core idea (sliding window)

Maintain a window [left, right] that always contains unique characters. Move right one step at a time. If the new character is already inside the window, jump left just past its previous occurrence.

We store lastIndex: character → last index seen. A duplicate only matters if that index is still ≥ left (still inside the window). Older occurrences outside the window are ignored.

Code mapped to the diagrams

public static int lengthOfLongestSubstring(String s) {
    if (s == null || s.isEmpty()) {
        return 0;
    }

    Map<Character, Integer> lastIndex = new HashMap<>(); // char → last index
    int maxLength = 0;
    int left = 0;                                         // window start

    for (int right = 0; right < s.length(); right++) {     // expand window
        char c = s.charAt(right);

        // Duplicate still inside [left, right]? Jump left past it.
        if (lastIndex.containsKey(c) && lastIndex.get(c) >= left) {
            left = lastIndex.get(c) + 1;
        }

        lastIndex.put(c, right);                          // record latest index
        maxLength = Math.max(maxLength, right - left + 1);
    }

    return maxLength;
}

Complexity & pitfalls

  • Time: O(n) — each index is visited once by right; left only moves forward.
  • Space: O(min(n, charset)) for lastIndex.
  • Why not nested substrings? Checking every i..j is O(n²) or worse; the broken sketch in earlier attempts did that.
  • Must check >= left: without it, an old index outside the window would incorrectly shrink left.
Interview one-liner: sliding window + last-seen index map; on duplicate inside the window, jump left past it and track max window size.
